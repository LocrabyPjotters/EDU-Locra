Cryptografisch Beveiligingswhitepaper

De Wiskunde en Hardware achter Zero-Access AI

Hoe Locra PrivAI™ garandeert dat zelfs met fysieke servertoegang of root-rechten niemand jouw prompts of persoonsgegevens kan ontcijferen.

⚡

1. AMD SEV-SNP Hardwarematige RAM-Encryptie

Secure Encrypted Virtualization – Secure Nested Paging

Traditionele servers slaan gegevens tijdens de berekening onversleuteld op in het RAM. Een beheerder met root-toegang, een gecompromitteerde hypervisor of een aanvaller met een hardwarematige RAM-interceptor (cold-boot aanval) kan al die data rechtstreeks uitlezen.

Met AMD SEV-SNP versleutelt de geheugencontroller op de CPU zélf het werkgeheugen realtime met willekeurige AES-128/256 sleutels. Deze sleutels worden gegenereerd in de geïsoleerde AMD Secure Processor (ASP) op het silicium en verlaten de chip nóóit. Zelfs de hypervisor en het besturingssysteem van de host-server zien uitsluitend willekeurige ciphertext.

🔐

2. End-to-End Cryptografische Envelope

X25519 ECDH + HKDF-SHA256 + AES-256-GCM

Voordat de prompt van de school vertrekt, vraagt de client de publieke sleutel van de TEE-enclave op via /v1/attestation. De client voert vervolgens een Elliptic-Curve Diffie-Hellman (ECDH) sleuteluitwisseling uit via Curve25519.

De prompt wordt lokaal verzegeld met AES-256-GCM (12-byte unieke nonce, 16-byte authentication tag). De Locra API Gateway in Amsterdam fungeert als 'Blind Proxy' en geeft het versleutelde pakketje ongewijzigd door aan de TEE enclave. Alleen de privésleutel die binnen de enclave is gegenereerd, kan het pakketje openen.

📜

3. Remote Attestation (Bewijsbare Integriteit)

Geen blind vertrouwen, maar cryptografisch bewijs

Bij gewone clouddiensten moet je blind geloven dat de server geen achterdeurtjes heeft. Met Remote Attestation ondertekent de processor zelf een rapport waarin de exacte SHA-256 hash van het draaiende besturingssysteem en de model-inferentiecode staat.

De SDK van de school controleert deze handtekening tegen de officiële AMD silicon certificaatketen. Zou iemand op de server stiekem een log-instructie toevoegen, dan verandert de hash direct en weigert de client de verbinding.

🧹

4. Ephemeral RAM Scrubbing (Zero Retention)

Geen sporen achterlaten in het geheugen

Zodra de laatste streaming-token via SSE is verzonden naar de school, activeert de enclave de geheugen-scrubber. De geheugensegmenten waarin de prompt, tokens en matrixactivaties stonden, worden overschreven met pseudowillekeurige ruis en vervolgens gevuld met cryptografische nullen (0x00).

Er is geen persistentie op schijf, geen swap-file en geen caching tussen verschillende verzoeken.
